# 海信电视局域网控制方案与验证记录

本文记录海信电视在局域网内的发现、控制、能力探测和待机唤醒测试结果，供后续接入 Home Assistant 或语音助手使用。

## 1. 结论摘要

- 当前最可靠的控制方案是电视 `7778/TCP` 上的轻量级 HTTP 遥控服务。
- 该服务无需配对或 MQTT 登录；电视开机在线时可以直接发送遥控按键。
- `KEY_VOLUMEUP` 已由实机画面/音量变化确认成功，不只是 HTTP 返回成功。
- `7778` 主要提供设备识别、简单能力查询和遥控按键注入，不是完整的电视状态管理 API。
- 标准 Wake-on-LAN、双 MAC 唤醒以及 `KEY_POWER` 待机唤醒均未成功。当前只能确认“现有设置和已知开放协议无法唤醒”，不能据此断定硬件绝对不支持网络唤醒。
- `36669` 和 `38400` 属于另外两套服务，当前尚未验证它们能提供比 `7778` 更稳定的遥控能力。

## 3. 已验证的 7778 HTTP 协议

基础地址：

```text
http://192.168.0.32:7778
```

### 3.1 获取设备 ID

```http
GET /..deviceid HTTP/1.1
Host: 192.168.0.32:7778
Connection: close
```

返回纯文本设备 ID：

```text
8610030090000050000005054ceed3ad
```

### 3.2 查询本机能力

```http
GET /..hisharecapacity HTTP/1.1
Host: 192.168.0.32:7778
Connection: close
```

实机返回：

```json
{
  "deviceid": "8610030090000050000005054ceed3ad",
  "voiceversion": "217860080",
  "smartimage": "1"
}
```

字段解释：

| 字段 | 含义 |
|---|---|
| `deviceid` | 电视唯一设备标识 |
| `voiceversion` | 语音交互模块或协议版本 |
| `smartimage` | 智能图像能力标志；`1` 表示支持或启用 |

这个接口不会返回完整按键列表，也没有当前音量、信号源、电源状态或 `wifiWakeSupported` 字段。

### 3.3 发送遥控按键

请求格式：

```http
PUT /<KEY>..controller HTTP/1.1
Host: 192.168.0.32:7778
Connection: close
```

已实机确认的示例：

```bash
curl --request PUT \
  --max-time 5 \
  'http://192.168.0.32:7778/KEY_VOLUMEUP..controller'
```

正常情况下返回 `HTTP 200`，且电视音量实际增加。

## 6. 当前确认的能力边界

`7778` 已确认适合：

- 获取设备 ID；
- 获取少量能力标志；
- 注入遥控器按键；
- 在电视开机在线时执行音量和导航类操作。

`7778` 目前没有发现以下接口：

- 查询当前音量数值；
- 直接把音量设置为指定数值；
- 查询或切换到指定信号源；
- 查询正在播放的内容；
- 查询可靠的开关机状态；
- 启动指定应用；
- 截屏、投屏或媒体推送；
- 从当前待机状态唤醒电视。

UPnP 媒体控制、投屏以及海信云端控制不应与 `7778` 混为一套协议。

## 7. 待机与 Wi-Fi 唤醒测试

用户将电视切换到正常待机后，完成了以下测试：

1. 向 Wi-Fi MAC `50:ba:02:cd:1c:86` 发送标准 Wake-on-LAN 魔术包；
2. 向有线 MAC `a0:00:4c:ee:d3:ad` 发送标准魔术包；
3. 使用 `192.168.0.255`、`255.255.255.255` 和电视 IP 作为目标；
4. 覆盖 UDP `7`、`9`、`36669`、`50000` 等常用端口并重复发送；
5. 尝试 `PUT /KEY_POWER..controller`；
6. 尝试 `PUT`、`POST` 到 `/..controller`，请求体为 `{"key":"KEY_POWER"}`；
7. 持续请求 `/..deviceid` 作为应用层在线检测。

结果：电视没有恢复应用层响应，标准 WOL 和已知 `7778` 电源请求均未唤醒电视。

这项结果只说明当前设置和当前固件状态下，已知开放协议无法唤醒电视。可能原因包括：

- 电视中的“网络唤醒”“手机唤醒”或“快速开机”没有启用；
- 固件不接受标准 Wake-on-LAN；
- “海信爱家”使用海信云端或 MQTT 专用唤醒通道；
- 区域版本、系统版本或待机模式不同。

后续最关键的对照实验是：保持电视待机，在“海信爱家”中点击一次开机。如果 App 能唤醒，就可确认硬件与固件支持唤醒，只是需要继续还原 App 的专用通道。

### 在线状态判断注意事项

当前电脑网络环境中，`nc` 对电视和未分配的局域网 IP 都可能报告任意 TCP 端口连接成功，因此不能使用单纯的 TCP connect 结果判断电视是否在线。

推荐使用应用层检查：

```bash
curl --fail --silent --show-error \
  --max-time 2 \
  'http://192.168.0.32:7778/..deviceid'
```

只有收到正确的设备 ID 响应，才能确认电视主系统和 `7778` 服务已经恢复。

## 8. 85E7N 网络唤醒资料结论

- 中国版 85E7N 的官方商城参数确认支持有线和无线网络，但没有明确标注 Wake-on-WLAN 或断电恢复后的网络唤醒：[海信官方商城 85E7N](https://mall.hisense.com/items/5882)。
- 海信日本官方 FAQ 将 E7N 系列列为适用系列，并说明支持 AirPlay 或 YouTube 的电视可被同一网络中的手机等设备启动：[海信日本 E7N 系列 FAQ](https://faq.hisense.co.jp/faq/show/8854?category_id=8&site_domain=hisense)。
- 海外 E7N 与中国版 85E7N 可能使用不同系统和固件，因此海外资料只能作为系列能力参考，不能替代中国版实机测试。
- 电视断电时 Wi-Fi 模块没有供电，不可能接收唤醒包。重新供电后是否能唤醒，取决于网络模块是否自动启动并连接 Wi-Fi。用于可靠自动化时，应优先查找“通电开机”“上电开机”或“开机模式”设置。

## 9. 如何确认 7778 的完整实用能力

`/..hisharecapacity` 不会枚举全部 API。确认完整能力需要组合以下方法。

### 9.1 分析官方客户端

继续从“海信爱家”客户端中提取：

- 所有包含 `7778` 的请求；
- 所有 `/..` 路径；
- 所有 `KEY_*` 字符串；
- 请求方法、请求体和必要请求头；
- 本地控制与 MQTT/云端控制的分支条件。

目前已经从客户端中确认 `/..deviceid`、`/..hisharecapacity`、`..controller` 和上表中的 13 个按键。

### 9.2 抓取海信爱家实际流量

这是确认 App 实际使用能力的最可靠方法。电视开机后，在 App 中逐项操作音量、方向、信号源、播放控制和应用入口，同时抓取手机与电视之间的流量。

如果路由器运行 OpenWrt 或支持 SSH 抓包，可使用：

```bash
tcpdump -i br-lan -s0 -w hisense-7778.pcap \
  host 192.168.0.32 and tcp port 7778
```

Wireshark 显示过滤器：

```text
ip.addr == 192.168.0.32 && tcp.port == 7778 && http
```

抓包设备必须位于手机与电视的实际通信路径上。普通情况下，仅在另一台连接同一 Wi-Fi 的电脑上监听，通常无法看到手机到电视的单播流量。

### 9.3 安全按键枚举

电视开机后，可以对常见按键字典逐项发送请求，并记录：

- HTTP 状态码；
- 响应体；
- 电视屏幕或声音是否实际变化；
- 是否能够恢复测试前状态。

不要无边界随机模糊测试。电视内置 WebServer 较轻量，未知路径、异常长请求或高并发可能导致固件卡顿。优先测试从官方客户端、同系列固件或遥控器按键表中发现的候选值。

### 9.4 完整固件分析

如果目标是证明固件中“所有隐藏接口”，最终需要分析电视端提供 `7778` 服务的可执行程序。对 Home Assistant 集成而言，官方 App 抓包加安全按键枚举通常已经足够。

## 10. 安全建议

- 不要把 `7778`、`36669` 或 `38400` 端口映射到公网；
- 该 HTTP 遥控协议未发现认证机制，同一局域网内的其他设备可能直接控制电视；
- 建议将 IoT 设备放入受控 VLAN，并只允许 Home Assistant 主机访问必要端口；
- 自动化中应设置请求超时、低频重试和明确的按键白名单；
- 电源和系统更新相关按键应谨慎测试，避免循环开关机或打断固件升级。
